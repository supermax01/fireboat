Applied root-owned package.json entry (B2-0):

  "test:isolation": "node tests/isolation/run.mjs"

run.mjs sets one B2_RUN_ID and a fresh random B2_ATTEMPT_ID (exclusive attempt.json),
runs every tests/isolation/*.test.ts (the prerequisites in
isolation.test.ts, the counting machinery in counting.test.ts, the oracles, and one
family shard per cases-<fam>.test.ts), then runs tests/isolation/aggregate.ts, which
joins artifacts/b2/<run>/prerequisites.json with one shard per selected family, refuses
any file whose recorded start or end binding (candidate/run/attempt digest, source
and emitted build, pins, dependency hashes, selection environment and the end
case-report digest) differs from its own, verifies the manifest pins and the ledger's design
digest, computes the gate on the candidate inputs digest, and writes
artifacts/b2/<run>/report.json plus artifacts/isolation-v1-report.json. Either step
failing fails the run. Do not edit tracked files while a run is in progress: the end
bindings would differ and the aggregate would refuse the run.

Kill evidence: `node tests/isolation/run.mjs --with-kills` judges the kill-matrix rows
and runs the diagnostic under the same random attempt. A reused run directory is
refused. `node tests/isolation/mutants.mjs --run <id>` remains a standalone diagnostic;
its output cannot be relabelled into another run/attempt for credit. The aggregate
validates row anchors, compilation, baseline, designated oracle failures and spares;
summary-only KILLED labels never earn credit. A failed kill child fails --with-kills.

Budget provenance: a counted case's budget_source names artifacts/b2/<run_id>/report.json
by run id, report SHA-256 and binding SHA-256; keep those verified six-cell measurement
reports, which the aggregator re-reads and validates.

The registry judge (scripts/mutation-guards.mjs) runs the isolation files as ordinary
node tests: an INCONCLUSIVE case is a named failure of its case test there, while the
B2 report and mutants.mjs keep INCONCLUSIVE distinct from FAIL (D10).

Root should pin action revisions and the image digest under its normal CI policy.
Do not treat this job as an acceptance/release gate. A failing diagnostic exits
nonzero; continue-on-error is the explicit CI policy, never an xfail in the suite.
The image must already contain all pinned dependencies; no npm install or public
network access occurs during execution. All backend and sink listeners bind to
127.0.0.1 inside the same container/network namespace. No ports are published.
The macOS execution is diagnostic and does not establish OS-level egress denial.
A separate root-owned Linux egress-enforcement check is still required.
