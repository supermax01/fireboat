# Rename plan: fireboat

- **Decision (owner, 2026-10-22):** repository `fireboat`, npm package `@fireboat/gateway`, CLI `fireboat`. The rename is prepared now and applied at the S8/S9 packaging step. It is not applied on `r/s5-candidate`, and no publish, push, tag or repository rename happens without a separate owner approval at the time.
- **Why one commit:** the server name sits inside the measured catalog boundary (`serverInfo.name` is part of the "complete" listing), the fixture pins hash the listing, the generated contract and example captures carry the identity, and docs quote the CLI. A partial rename would leave the evidence inconsistent.

## Steps at the packaging slice

1. Branch from the accepted S7 tree; apply the table above in one commit.
2. `npm run build` (the post-build identity check now expects `fireboat <version>`), `npm run check`, isolation, both eval eras, demos.
3. Re-capture the listing (`scripts/capture-tool-catalog.ts`), re-run the exploratory measurement, re-pin `tests/fixtures/s58-release-catalog.json`, regenerate `docs/contracts/m3b-tools.json` and `examples/tool-calls.json`; record the byte and token deltas (the catalog headroom grows by the shortened name).
4. Regenerate the S7 docs from the renamed identity.
5. Mutation anchors: no registry anchor contains the old name today (`scripts/mutation-guards.mjs` has none); confirm with `tests/mutation-anchors.test.ts`, refresh `hashes.mutants` only if the registry changed.
6. Independent review pass, then the 14-shard aggregate on the renamed tree.
7. Owner actions, each separately approved: GitHub repository rename, `@fireboat` scope claim, and later the tag, npm `alpha` dist-tag, OCI push and Registry entry.
