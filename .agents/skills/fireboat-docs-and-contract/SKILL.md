# Tool contract and generated docs

## The tool contract

Everything a host sees (the five tool descriptions, their schemas and the server instructions) is measured against byte caps in `docs/contracts/m3b-tools.json`. Some tools sit exactly at their cap, so every byte counts.

After changing any of it:

```sh
node --import tsx scripts/emit-m3b-contract.mjs --check     # contract is current; regenerate without --check
node --import tsx --test tests/m3b-contracts.test.ts tests/m3b-catalog-v2.test.ts
```

- A wording change needs a fresh catalog capture (`scripts/capture-tool-catalog.ts <empty-dir>`), and must keep each tool's bytes within its cap.
- Raising a cap needs a measured, task-linked reason in the pull request.

## Generated reference docs

`docs/SUPPORT-MATRIX.md`, `docs/support-matrix.json`, `docs/QUERY-EVIDENCE.md`, `docs/COMPACT-PROFILES.md`, `docs/HOST-PROFILES.md` and `docs/QUERY-REPAIR.md` are generated from code and data by `scripts/generate-m3b-docs.ts`. Each starts with a "Generated by" comment.

```sh
node --import tsx scripts/generate-m3b-docs.ts --check   # fails on drift
node --import tsx scripts/generate-m3b-docs.ts           # regenerate after changing their inputs
```

Never hand-edit them; `tests/m3b-docs-sync.test.ts` checks them byte for byte.

## Prose docs

`README.md`, `docs/LIMITS.md`, `docs/QUICKSTART.md` and `SECURITY.md` are hand-written. Keep them factual: every claim must match a recorded check, and the non-claims in `proposals/release-plan.md` §8 hold.
